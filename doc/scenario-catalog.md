# Test Scenario Catalog

## Scope and evidence

Covers the observed public login, registration, and password-set screens plus ecommerce features and routes declared by the public client bundle. Bundle-declared behavior is not an approved product/API contract. Public UI and client bundle were inspected anonymously on 2026-10-01; no successful authentication or account/cart/order mutation occurred.

All requirement links are `TBD`. Discovery action: obtain approved requirements, acceptance criteria, API schemas, and authorization policy from product/service owners, then map each requirement before acceptance sign-off. Likely layers are recommendations, not automation commitments. Detailed cases: [UI](ui-test-cases.md), [functional](functional-test-cases.md), and [API](api-test-cases.md).

## Coverage note

These 26 scenarios map the discovered public UI and client-declared ecommerce surface, not approved acceptance requirements. Requirement coverage cannot be measured until owners supply requirements/contracts. The case catalogs distinguish executed, partial, failed/candidate, inconclusive, and unrun checks; scenario design is not execution evidence.
